## 为什么版本号直接跳到 2.0

因为从这个版本开始，AIDBM 不只备数据库了——**AI 大模型工作负载的全部持久化状态**（模型权重、训练数据集、向量索引、关系元数据、编排配置、数据血缘、Agent 状态）正式进入保护范围，并且是以"跨层一致性恢复单元"而非"一堆独立文件"的方式来保护的。

灾备平台保护的对象变了，保护的方式也必须升级，这值得一个大版本。

## 一、AI 大模型数据备份（v2.0.0 核心）

### 1.1 七层状态模型：别再把 AI 系统当成"无状态容器 + 权重文件"

一个能运行的大模型服务，至少协调着七层相互依赖的持久化状态。任何一层单独恢复而其他层不同步，系统都可能**看似启动、实则输出错误**。AIDBM 按层清点、按层保护：

| 层 | 资产 | AIDBM 保护方式 |
|---|---|---|
| ① 模型权重与检查点 | .safetensors / .gguf / LoRA / 微调产物 | 文件备份 + 源端去重（实测节省 95.5% 带宽）+ 不可变锁定 |
| ② 训练与微调数据集 | 语料 / 清洗集 / 标注 / prompt 日志 | 不可变保留（WORM 语义，防清洗流程误覆盖） |
| ③ 向量索引 | HNSW/IVF 二进制（重建 = 数十小时 GPU） | **Qdrant / Chroma 原生引擎**（本轮新增） |
| ④ 关系型元数据与对象存储 | 用户/会话/审计库；PDF/音频/图片 | 全库型备份矩阵 + 对象存储桶级保护 |
| ⑤ 编排与运行时配置 | K8s 清单 / GPU 环境 / 路由规则 | 文件备份（增量/排除规则） |
| ⑥ 版本指针与数据血缘 | DVC .dvc / lakeFS 提交 / 实验 run ID | 文件任务承接（指针 + 提交历史） |
| ⑦ Agent 执行状态 | 任务状态 / 工具链 / 权限边界 | 文件/数据库任务承接 |

### 1.2 向量数据库原生引擎（不是"当普通目录拷贝"）

直接对向量库存储目录做文件快照，在活跃写入时会捕获不一致的内部状态。本轮新增两个原生引擎：

- **Qdrant 引擎**：走 Qdrant 官方 REST 快照 API（创建 → 流式下载 → 清理远端 → 恢复上传 `priority=snapshot`），支持异名恢复（恢复到新 collection）、api-key 认证、按 collection 或全实例备份。**纯 HTTP，零安装零 Agent**——被保护的向量库服务器上什么都不装。
- **Chroma 引擎**：目录快照 + SQLite 完整性校验 + manifest；如实标注边界——活跃写入窗口的一致性由调用方停写保证（Chroma 无在线快照 API，我们不假装它有）。

### 1.3 AI 保护计划：跨层一致性恢复单元（本轮最硬核的设计）

这是对"备份平台是否真正保护 AI 负载"的核心判断标准的直接回答：

> 备份平台是否把「向量索引 + 嵌入模型版本 + 关系元数据 + 对象存储」当作一个**不可拆分的恢复单元**来对待。

AIDBM 的 AI 保护计划把多层资产编入同一恢复单元，一次运行：

1. **按序驱动**组内所有成员任务备份（复用全部既有引擎能力）；
2. 产出**组恢复点（epoch）**= 所有成员最近成功备份时间的最小值；
3. 量化**层间偏差（drift）**并对照阈值——偏差超限即 WARNING 告警：
   *"向量索引快照在 10:00、关系库在 14:00，外键断裂、文档 grounding 失效，系统会输出看似合理但完全错误的引用"*——这种事故从"没人发现"变成"备份报告里红字可见"；
4. 单成员失败不中断组，报告如实标注，**不伪装成功**。

诚实边界（写进文档的那种）：协调一致 ≠ 存储层原子快照（后者需要文件系统/存储控制器级一致性组，离线零 Agent 架构不做）；嵌入模型版本不在向量库快照内，必须通过保护计划与索引绑定——报告会强制提示这条绑定关系。

## 二、容灾自动化：从"能切"到"自动切、切得回"

### 2.1 自动切换监控（P1-1）

- 主库健康探测 + 连续 N 次失败策略（探测间隔/阈值可配，带下限钳制）；
- 两级处置：只告警（默认）或**自动 failover**（require_manual_confirm=false）；
- 自动切换复用完整 FailoverEngine 链路：**Fencing 冻结旧主 → 提升备库 → DNS 切换（解析回读验证）→ 新主验证**，RTO 实测 **15 秒级**；
- 切换向导：预检快照 → 确认 → 执行 → RTO 分步报告，全程页面可见。

### 2.2 GTID 分叉保护：自动回切的最后防线（真机实证）

本轮真机测试中，failback 引擎**成功拦截了一次真实的分叉态**：旧主存在现主缺失的事务来源时，引擎拒绝自动回切并给出处置指引（a 丢弃分歧数据 / b 导出合并）——**宁可拒绝回切，绝不静默丢数据**。人工收敛（重新对齐 GTID 记账）后回切一次通过。

### 2.3 170/171 真机全流程验证

| 场景 | 结果 |
|---|---|
| 自动监控触发 failover（连续失败 → fencing → 提升 → DNS 切换） | ✅ 全步骤 PASS |
| failback（rejoin 追平 → 提升 → 转从 → DNS 切回） | ✅ RTO 15.0s |
| 切换期写入硬核对 | ✅ 170 写 → 171 从库可见 |
| 最终拓扑 | 170 主 / 171 从（IO/SQL=Yes，延迟 0） |

## 三、备份性能：单任务多通道并行（P1-5）

对标商业产品 RMAN 多通道能力：

- **Oracle RMAN 多通道**：任务级配置 2-8 通道，RUN 块内显式 `ALLOCATE CHANNEL`，备份集自动分片到各通道并行写盘；恢复校验（VALIDATE）同样受益。真机实测（129 Oracle 19c）：**19 个备份片 / 496MB / 4 通道**。
- **备份片并行拉回**：RMAN 多备份片 / pg_basebackup 多 tar 包时，多条独立 SSH 连接并行 SFTP 拉回——真机实测 **4 线程并行拉回**；任务级限速视为总带宽按线程均分；单片断点续传语义完整保留。
- 单连接场景脚本与旧版逐字节一致，**零破坏**。

## 四、Oracle 事务级精准还原（P1-2）

误删一条数据，不再需要整库时点恢复：

- LogMiner 实时捕获（含 **XID 事务标识**，真机核实列名并修复）；
- 按事务聚合浏览：时间轴 + 操作计数 + SCN 区间 + 对象清单；
- 回滚计划：**SCN 降序反向回放 SQL_UNDO**（Oracle 官方反向回滚语义），DDL 无 undo 如实标 skipped；
- 执行：逐条独立提交、错误隔离，结果逐条回传。
- **129 Oracle 19c 真机全链 6/6**：真实 DML（2 插入 + 1 更新 + 1 删除）→ 捕获 → 计划 4 条 UNDO → 执行 0.02s → **行级硬核对 pre/post 完全一致**。

## 五、池复制两地三中心（P1-3）+ 文件实时同步（P1-4）

- **池复制**：把存储目标组织成 production → same_city → remote 的作业链（serial 逐级级联，上游失败下游 skipped"级联中断"；parallel 扇出并行）；备份成功自动触发复制；副本分布视图 + **异地取回**（逐字节 sha256 校验一致）。真机 S3 两地 E2E **6/6**。
- **文件推送式实时同步**：SSH 只读指纹扫描（find+sha256sum，零临时文件）→ 指纹 diff → 仅拉变更文件 → 版本目录保留（.deleted.txt 记录删除）；排除规则、keep_versions 清理、30s 调度 tick + 任务级节流。**零 Agent 替代 inotify**，E2E 12/12。

## 六、安全与可靠性（持续加固）

- **高危操作验证码**：恢复/清理/删除任务/删除主机可开启二次验证码（session 一次性 4 位码，5 分钟有效，防重放）；
- **资源受保护标记**：纳管主机可标记"受保护"，恢复/演练目标命中即硬闸拒绝（覆盖全部恢复入口）；
- **协作式取消**：备份停止在传输块边界生效、断点保留可续传；Agent 通道断连秒级 killpg（不留孤儿进程）；
- **僵尸状态自愈**：服务中断后的僵尸 running 状态启动时自动修正，前端"停止"按钮只在真实有执行中记录时显示；
- **跨库校验修复**：异构目标（MySQL→达梦等）校验器不再按 MySQL 方言硬跑，降级为行数对账并如实标注。

## 七、系统全景：AIDBM 现在能做什么

### 备份矩阵（零 Agent，被保护服务器不装任何东西）

- **数据库**：MySQL / MariaDB / PostgreSQL / Oracle（11g-19c）/ SQL Server / 达梦 / 金仓 / openGauss / 磐维 / Redis / MongoDB / Neo4j，逻辑 + 物理 + 增量链 + PITR
- **实时备份（CDP）**：MySQL binlog / PG WAL / Oracle LogMiner / 达梦/金仓日志流，任意时间点恢复
- **文件**：全量/镜像/增量/排除规则/源端去重/rsync delta/断点续传/不可变锁定
- **对象存储**：MinIO / S3 / OSS / COS 桶级保护
- **虚拟机**：ESXi / Hyper-V / libvirt / PVE（SSH 通道）
- **AI 工作负载**：v2.0.0 新增（见上文）
- **自定义脚本**：任意 backup_mode=custom，脚本环境变量平台注入

### 恢复与验证

- 单表/多表直接恢复（从全实例包抽表）、异名库恢复、跨主机恢复、PITR、Oracle 事务级回滚
- **恢复校验真实化**：impdp SQLFILE 解析、RMAN RESTORE VALIDATE + 数据文件真实抽取
- **真实恢复演练**：定期自动恢复到隔离库 + 行数逐表核对 + 评分
- 数据对比：恢复库 vs 生产库逐行/抽样/checksum

### 基础设施

- 存储池：local / MinIO / S3 / 磁带，池复制两地三中心、生命周期分层
- 元数据库可插拔（SQLite 默认 / PG / MySQL）
- 全离线交付：镜像/离线包自带全部依赖（Python 驱动、JDBC+JRE、xtrabackup、达梦驱动），运行时不联网装任何东西
- 数据同步/迁移：全库型迁移向导 + 增量/实时同步 + 断点续传 + 对账
- 插件市场 + 数据库部署引擎 + DNS 容灾记录管理 + Webhook 事件中心 + 智能告警

### 三条底线（写在所有文档里）

1. **真实执行不仿真**：能力不足如实 FAILED，绝不产出假数据；
2. **零 Agent**：被保护服务器（尤其数据库服务器）不装任何工具，物理备份工具平台侧临时推送用完即清；
3. **完全离线**：最终交付形态为 air-gapped 环境，一切依赖随包自带。
