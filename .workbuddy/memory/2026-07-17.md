## 修复：数据库引擎支持「无客户端时远程 SSH dump」（核心痛点）
用户痛点：备份服务器若没装 mysqldump/pg_dump，MySQL/PostgreSQL 引擎直接回退到仿真占位，不是真实备份；且文件备份归档只落在内部 storage 目录，用户在自己配置的 target_path 找不到文件。

### 改动
- **`core/remote_dump.py`（新建）**：`resolve_ssh_host(task)` 解析 SSH 主机（优先级：extra_options.ssh_host_id 显式指定 → 按 task.host IP 匹配 ssh_hosts 的 hostname/host_key）；`remote_db_dump` / `remote_db_restore` 通过 paramiko 在数据库服务器本机(localhost)执行 mysqldump/pg_dump，把字节流回传备份服务器落盘——**不依赖备份服务器装客户端、不装 Agent**。复用 file.py 的 `_get_ssh_client`/`_ssh_exec_pipe`（保持 bytes 保真）。数据库账号密码仅用于数据库；SSH 走 ssh_hosts 已加密凭据。
- **`core/engines/base.py`**：新增 `_write_dump_file()` 公共方法（远程字节流落盘 + size/checksum + SUCCESS）。
- **`core/engines/mysql.py` / `postgresql.py`**：重构 backup/restore 分发逻辑——
  - `demo_only` 或 `DEMO_MODE=on` → 仿真占位（用户显式选择）；
  - 本机有客户端 → 真实本地备份（原逻辑抽取为 `_backup_local`/`_restore_local`）；
  - 本机无客户端 + 解析到 SSH 主机 → **真实远程 dump/restore**（不再仿真）；
  - 既无客户端也无 SSH 主机 → 才仿真占位并给出明确原因。
  - 两个文件补 `import config`（原漏 import 导致 NameError）。
- **`core/engines/file.py`**：`_full_transfer`/`_incremental_transfer` 在目标为 local 且配置了 target_path 时，归档直接写入用户指定目录（不再只落内部 storage），用户能在自己配置的路径找到备份文件。
- **`templates/base.html`（DB 任务模态框）**：新增「SSH 主机（无客户端时远程执行 dump）」下拉框 + 说明文字。
- **`static/js/app.js`**：`initTasks` 预载 /api/hosts 并填充该下拉；`openTaskModal` 回填 `ssh_host_id`；`saveTask` 将 `ssh_host_id` 写入 `extra_options` 下发。

### 验证
- py_compile 全过；app.js `node --check` 通过。
- 针对性冒烟 13/13 PASS（含 monkeypatch 验证 MySQL/PostgreSQL 在无本机客户端时确走远程 dump 且产出真实非仿真文件；文件备份归档确落在 target_path；resolve_ssh_host IP 匹配与显式 id 匹配；test_client 导入无错、meta 401、file_backup 可达）。

### 关键结论（给用户）
数据库备份不再"过度依赖服务端装客户端"：只要在被备份的数据库服务器上纳管了 SSH 主机（文件备份页的「纳管主机」即可复用），备份平台就会 SSH 登录该库服务器就地 dump 并回传，**无需在备份服务器安装 mysqldump、也无需在被备份机装 Agent**。数据库任务表单新增的「SSH 主机」下拉即用于此。

## 修复：彻底移除「无客户端自动仿真」(2026-07-18)
用户核心诉求：数据库备份和文件备份不要自动回退到仿真占位，必须是真实执行。

### 根因
`config.DEMO_MODE` 默认为 `"auto"`，导致 `_should_simulate()` 在检测到本机缺少客户端工具时自动返回 `sim=True`，引擎走仿真占位从未真正执行 dump/tar。

### 改动
- **`config.py`**：`DEMO_MODE` 默认值从 `"auto"` → `"off"`。只有显式勾选演示或设环境变量才仿真。
- **全部 8 个引擎**：移除 `_should_simulate()` 调用，改为 `demo_only`/`DEMO_MODE=="on"` 二选一。
- **`mysql.py`/`postgresql.py`**：`backup()`/`restore()` 不再用 `check_client()` 门控——始终先尝试本机 `_backup_local`/`_restore_local`；失败则 SSH 远程；两路都失败返回 `BackupResult(success=False)` 真实错误。
- **补 `import config`**：`file.py`、`mongodb.py`/`kingbase.py`/`redis.py`/`dameng.py` 原来引用 `config.DEMO_MODE` 但未 import，已补。
- 全部文件 py_compile 通过；真实启动 run.py（DEMO_MODE=off）无 import 异常，路由正常。
