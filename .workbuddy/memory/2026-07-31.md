## VM 级 CDP 技术调研（用户要求引入 CDP 做虚拟机实时备份/克隆）
- 输出报告 `docs/cdp-vm-clone-research.md`（架构师高见远，1476 行，6 张 Mermaid 图）。
- **核心结论**：VM 级"真 CDP"（秒级/IO 级）开源无法集成（全为商业闭源内核态 IO 过滤，需 Hypervisor 厂商授权）；可落地的是**准 CDP**（块级变更跟踪 CBT/RCT/dirty-bitmap + 高频增量 + PIT 恢复点日志），与本平台"全量+增量+备份集链"模型同构。
- **主推方案 A**：`core/vm/` 统一抽象层 + Proxmox VE/PBS Provider（纯 Python `proxmoxer`，无 C 依赖，PBS 原生块级去重+dirty-bitmap 增量+任意点 `qmrestore` 克隆新 VM + live-restore 秒级 RTO）。约 15~20 人日。
- **次推方案 B**：vSphere CBT Provider（`pyVmomi` + NFC/HTTPS Range，**不引入 VDDK**），覆盖存量 VMware。约 +10~12 人日。
- 其余：KVM/libvirt（无 Windows 轮子，P1）/ Hyper-V RCT（P2）/ oVirt（Red Hat 已 EOL，不纳入）/ 商业（只纳管对接）。
- 集成方式：注册 `db_type="vm_cdp"` 复用现有任务 CRUD/调度/backup_records/三级存储/告警；新增 5 张表（`vm_hypervisors`/`vm_protected`/`vm_recovery_points`/`vm_consistency_groups`/`vm_clone_jobs`）加进 `core/db.py` 的 `SCHEMA` 自动建表；调度器必须 `max_instances=1 + coalesce=True`。
- **用户已确认**：不做 VM 级 CDP，只做数据库+文件级准 CDP 实时备份（DB 秒级日志 PITR + 文件分钟级近实时捕获）；管理端跨 Windows/Linux；采用方案 A 的准 CDP 哲学。
