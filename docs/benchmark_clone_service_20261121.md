## 1. 国际先进克隆服务的 12 项能力基线

| # | 能力 | 国际产品做法（谁做到什么程度） | AIDBM 现状 |
|---|---|---|---|
| 1 | **即时克隆（Instant Clone）** | Rubrik：COW 快照 + 写时复制，秒级出克隆件；Veeam Instant Clone：块级共享，秒级 | ⚠️ 仅有活库 COW 模式（PG 模板库 / MySQL LVM 快照），产物导入型克隆仍是分钟级 |
| 2 | **克隆件容量视图** | Rubrik/Veeam：克隆件列表直接显示占用容量与增长趋势；克隆前给容量估算 | ✅ **本轮落地**：交付即实测数据量 + 提交前容量视图（源产物/原始体量/预计占用/目标端可用空间） |
| 3 | **克隆前预检（Preflight）** | Delphix/Commvault：提交前校验产物、容量、连通性、隔离策略，失败即拦 | ✅ 已有预检 8 项（源状态/产物/校验值/端口/磁盘/凭据/隔离态），**本轮新增容量项** |
| 4 | **生命周期治理（TTL + 自动回收）** | Commvault/Zerto：克隆件默认 TTL，到期自动销毁；配额与成本可见 | ✅ 已有 TTL + `clone_expire` 调度 job；**本轮新增剩余有效期徽章（剩 N 天/N 小时/已过期）** |
| 5 | **克隆件校验（Verify）** | 主流产品克隆后可跑一致性/应用连通性检查 | ✅ 已有「校验」（表数/行数）+「接管检查」（直连/表数/行数抽样） |
| 6 | **克隆谱系（Lineage）** | Rubrik：克隆件 ← 快照 ← 保护组 全链路可追溯 | ✅ **本轮落地**（详情弹窗展示源记录/任务/库型/目标实例）；⚠️ 派生克隆（二次克隆）链路未串 |
| 7 | **克隆后测试编排** | Zerto Automated Testing：克隆件自动跑应用级测试并出报告 | ❌ 未做（只有接管检查） |
| 8 | **克隆件接管/割接** | Zerto：克隆件可一键切生产（含 DNS/VIP 牵引、就绪门禁） | ⚠️ 有接管检查 + 用途 emergency 标记；❌ 无一键割接编排（容灾切换在 /dr 域，未与克隆件打通） |
| 9 | **网络/安全隔离** | Delphix/鼎甲：克隆件使用独立网络、独立端口、掩码脱敏 | ⚠️ 有异名库/schema 隔离；❌ 无独立网络/掩码 |
| 10 | **批量克隆 / 模板化** | 主流：一源多目标、批量申请、克隆模板 | ❌ 未做（单条申请） |
| 11 | **成本核算** | SaaS 型克隆服务：按「克隆件容量 × 存活天数」计费 | ⚠️ 有容量与 TTL，❌ 未做成本视图/排序 |
| 12 | **一致性与可用性标注** | Veeam：区分应用一致/崩溃一致/文件系统一致 | ✅ 只有崩溃一致（诚实标注）；⚠️ 未提供应用一致性选项（依赖 DBMS 自身） |

**结论**：AIDBM 克隆服务的**数据面能力**（真实克隆、预检、校验、接管、TTL 回收）已对齐国际主流；
差距集中在**体验层与规模化**：即时克隆（秒级）、克隆件容量/成本治理、克隆后测试编排、一键割接、
批量克隆与克隆模板、网络隔离与脱敏。

## 2. 本轮具体改动

### 2.1 页面与列表
- `static/js/app.js`：`Pager.slice("clones", rows, 15)` —— 每页 15 行，消除 10 行时的留白。
- 新增列「数据量」，三级口径（**不混算**）：
  1. **实测**（首选）：克隆就绪后对目标库实测的体量（字节）+ 表数/行数；
  2. **估算**：源库原始体量（未压缩，`original_size_bytes`）；
  3. **源备份产物占用**（压缩后文件大小）。
  体积为 0（InnoDB 小库统计未刷新）时改为显示「N 表 / M 行」并注明口径，不冒充字节数。
- 新增「详情」按钮 → 克隆件详情弹窗：源记录/任务/库型/目标实例/三档数据量口径/实测时间与说明/
  有效期/申请人/审批人/创建时间，并提供「重新实测数据量」。

### 2.2 后端
- `core/db.py`：`clone_requests` 增 `data_size_bytes / data_tables / data_rows / data_measured_at / data_note`（含存量库 ALTER 迁移）。
- `core/models.py`：列表与详情统一联查 `br.size_bytes / br.original_size_bytes / br.backup_path`；
  `update_clone_request` 白名单放行数据量字段。
- `core/clone_service.py`：
  - `measure_clone_size()`：复用 `core/restore_metrics.py` 实测目标库（直连优先、SSH 兜底），
    采不到**如实记录原因**，不猜数；
  - 克隆就绪后自动实测（best-effort，不影响克隆成功判定）；
  - `_decorate_sizes()`：派生 `source_size_human / source_original_size_human / data_size_human / ttl_hours / expired`；
  - 对外详情**不返回明文口令**（`include_secret=False`）。
- `core/clone_preflight.py`：`estimate_clone_size()` —— 提交前给出源产物大小、源库原始体量、
  克隆件逻辑数据量、目标端预计占用（逻辑导入 ×1.3；活库 COW ≈0）、目标端可用空间；
  空间不足时按 warning 提示。
- `api/clone.py`：新增 `POST /api/clone/<id>/measure`（随时重新实测）。

### 2.3 真机验证（生产 API 8080）
- 真实克隆：源记录 438（MySQL 本机实例）→ 目标 `127.0.0.1:3308` → **ready**，
  实测 **16.0 KB / 1 表 5 行**，源产物 852 B，源库原始体量 2.1 KB，剩余有效期 160 h。
- 预检容量视图：源产物 963 B / 原始体量 2.9 KB / 预计占用 3.8 KB / 目标端可用 1.9 GB。
- 采不到的情况如实报因：达梦克隆件目标实例已销毁 → 「直连采集失败：… Create SOCKET connection failure」。

## 4. 诚实边界

- 克隆件体量为**实测值**（直连优先，SSH 兜底）；MySQL 小库在 InnoDB 统计刷新前会显示 0B，
  此时按表/行数展示并在备注说明口径，**不推算、不冒充**。
- 活库克隆（PG 模板库 / MySQL LVM 快照 / Oracle schema）依赖源实例的存储能力，
  非 COW 场景（如普通 ext4/xfs）无法秒级克隆，平台会如实报错而不是降级成"假秒级"。
- 当前克隆件隔离手段是**异名库/schema/collection**，不含独立网络与数据脱敏。
- 克隆不支持块级增量，也不做跨库型实时同步。
