# AI 智能助手 PRD

## 1. 产品目标

让用户通过自然语言对话，真正驱动备份管理平台"动手做事"——既回答运维知识问题，又直接执行备份/巡检/查询等操作，消除"连上大模型却只能聊天"的断层。

## 2. 用户故事

- **As a** DBA, **I want** 用自然语言提问"最近备份有没有失败", **so that** 不必翻多个页面就能快速定位问题。
- **As a** 运维人员, **I want** 说"跑一次生产库巡检", **so that** AI 直接调用后端执行巡检并返回结果，无需手动操作界面。
- **As a** 新手用户, **I want** 多轮对话中逐步缩小范围（先问"哪些任务有告警"→再问"详情"→再执行恢复），**so that** 复杂操作流程被 AI 串联引导。
- **As a** 管理员, **I want** 危险操作（删除任务、全量巡检）被二次确认拦截，**so that** 误操作不会造成业务损失。
- **As a** 团队负责人, **I want** 会话记录持久保存且可追溯，**so that** 团队成员的 AI 交互历史不丢失、可审计。

## 4. 工具清单（MVP）

| 工具名 | 描述（LLM 视角） | 输入参数 | 返回结果 | 需确认 | 后端端点 |
|---------|------------------|----------|----------|--------|----------|
| `run_backup_task` | 立即触发指定备份任务 | `{task_id: string}` | `{status, started_at}` | ❌ | `POST /api/tasks/{id}/run` |
| `run_inspection` | 对指定主机运行巡检 | `{host_id: string, scope?: "full"\|"quick"}` | `{report_id, summary}` | ✅（scope=full时） | `POST /api/inspections/run` |
| `query_backup_records` | 查询备份执行记录 | `{task_id?: string, status?: string, limit?: int}` | `{records: [...]}` | ❌ | `GET /api/records` |
| `query_alerts` | 查询当前告警列表 | `{level?: string, task_id?: string}` | `{alerts: [...]}` | ❌ | `GET /api/alerts` |
| `query_storage_usage` | 查询存储空间用量 | `{storage_id?: string}` | `{total, used, free, percent}` | ❌ | `GET /api/storage/stats` |
| `query_task_list` | 列出所有备份任务 | `{type?: string, status?: string}` | `{tasks: [...]}` | ❌ | `GET /api/tasks` |
| `view_inspection_report` | 查看巡检报告详情 | `{report_id: string}` | `{items: [...], score, summary}` | ❌ | `GET /api/inspections/{id}/report` |

> 确认规则：涉及数据删除、全量巡检、批量操作时弹窗二次确认，LLM 返回 `confirm_required` 标记。

## 6. 验收标准

1. **意图准确率 ≥ 85%**：100 条测试话术，LLM 正确区分问答/执行操作。
2. **工具调用成功率 ≥ 95%**：MVP 7 个工具各跑 20 次，调用→返回无异常。
3. **流式首 Token ≤ 2s**：用户输入后 2 秒内出现首段响应文字。
4. **会话持久化**：关闭浏览器重新打开，历史对话完整可追溯。
5. **危险拦截率 100%**：所有标记 `confirm_required` 的操作，未确认时 0 次漏执行。

## 7. 待确认问题

1. **ReAct vs Function Calling**：OpenAI 兼容协议是否支持原生 function calling？若支持，是否优先用它而非自建 ReAct 循环？
2. **Token 限制与截断策略**：多轮对话上下文滑窗大小（4K? 8K?），超长历史如何摘要压缩？
3. **会话过期策略**：会话保留多久？是否自动归档超过 30 天的记录？
4. **LLM 调用鉴权**：工具执行时是否复用用户当前 session token，还是独立 API Key？
5. **并发与限流**：同一用户同时发起多个工具调用时，后端如何排队/限流？
6. **错误兜底**：LLM 返回幻觉参数（如不存在的 task_id）时，中间件如何拦截并提示？
7. **模型切换**：用户能否在对话中切换不同 LLM 模型（Z.ai/Qwen/DeepSeek 等）？
8. **工具扩展机制**：新增工具是否需要改前端代码，还是纯后端注册即可动态发现？
