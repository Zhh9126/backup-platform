## 存储功能「落地可用」专项检查 + 修复（QA 回归）
- **背景**：用户要求"检查之前的优化并完整测试，要真正的落地可用"。回顾发现此前已实现三层备份但存在真实可用性缺陷。
- **已修复的阻塞级 Bug（前端/后端不一致）**：
  1. **复制策略模态框字段名废弃**：前端 `openReplicateConfig`/`saveReplicateConfig` 读写旧字段 `replicate_l1_to_l2`/`replicate_l2_to_l3`/`replicate_l1_to_l3`，而**后端只读 `push_l1_minio`/`push_l2_s3`/`push_l3_local`** → 用户无法显示/保存复制策略（静默失效）。已重写前端读写新字段、模态框勾选项 ID 改为 `rep_l1_minio`/`rep_l2_s3`/`rep_l3_local`。
  2. **存储目标 tier 硬编码倒置**：前端 `saveStorage` 写 `tier = local→1, minio→2, s3→3`，与后端 `TYPE_META`(minio=1/s3=2/local=3) 相反 → MinIO 目标会被错误归入 L2 卡片，且 `lifecycle._l1_usage` 按 `tier=1` 查不到 MinIO。**已删除前端硬编码 tier，统一由后端 TYPE_META 推导**。
  3. **层级标签倒置**：存储类型下拉框 / 空状态文案原来标 minio=L2、s3=L3、local=L1，已改为 minio=L1、s3=L2、local=L3，并修正复制方向文案与空状态描述。
  4. **生命周期 L2→L3 死字段**：`lifecycle.run_once` 实际只做 L1→L2 下沉，`l2_to_l3_days` 已无用；为不破坏既有测试（qa_phase_0_1_2 断言其存在）保留后端字段，仅在前端标注"L3 为复制终态、不参与自动流转"。
- **测试加固**：`tests/qa_storage.py` 新增 `test_replication_config_roundtrip`（POST 新字段→GET 校验，且旧字段名不被白名单写入）；总用例 18 条。
