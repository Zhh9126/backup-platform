## 1. 产品概述

AIDBM 是面向企业级数据库灾备场景的一体化管理平台，核心定位：

- **零 Agent**：被保护的数据库服务器上不安装任何备份工具、Agent 或依赖；所有备份能力（含 xtrabackup 等物理备份二进制）由平台通过 SSH+SFTP 推送式临时执行，用后清理。
- **离线自足**：面向完全离线（air-gapped）环境交付，运行时不依赖公网 PyPI/DockerHub/NTP/AI API；所有数据库客户端工具、驱动、运行库随离线包自带，支持单向网闸/摆渡盘场景的数据同步。
- **多负载统一保护**：不止数据库——**文件/目录备份与镜像、文件实时同步、虚拟机备份（ESXi / Hyper-V / KVM-libvirt / Proxmox VE）、对象存储（S3 兼容整桶）、Redis/MongoDB/Neo4j/AI 向量库**与数据库同平台统一纳管、统一调度、统一恢复点与告警（各负载能力边界见第 4.3 / 4.4 / 13 章，如实标注）。
- **国产数据库一等公民**：达梦、金仓、openGauss、磐维等信创数据库与 Oracle/MySQL/SQL Server 等同级别深度支持，覆盖逻辑/物理/实时/克隆/PITR 全链路。
- **真实执行、如实失败**：所有备份、恢复、校验、演练均为真实操作，产物落盘、数据硬核对（行数+中文内容逐值比对）；失败如实报告真实原因，绝不仿真、绝不假成功。

### 3.2 版本兼容性设计原则

平台面向**新旧数据库版本共存**的现实环境设计，关键兼容机制均经真机验证：

- **客户端版本自动择优**：pg_dump/sys_dump/xtrabackup 等存在多版本候选时按 `--version` 解析取与服务器匹配的最高版本（实测规避 CentOS7 自带 pg_dump 9.2 无法备份 PG14 的问题）。
- **物理备份工具版本匹配**：MySQL 5.x → XtraBackup 2.4、8.0+ → XtraBackup 8.0，远端已装工具与服务器版本不符时自动忽略并推送平台侧匹配版本；远端 glibc 过低时自动推送配套运行库，无法解决时如实报错并引导改逻辑备份。
- **Oracle 11g/19c 双版本**：11g 无 thin 驱动自动切换 JDBC 兜底；19c CDB/PDB 场景自动处理（PDB 打开态检查、CDB 普通用户 C## 前缀、DATA_PUMP_DIR 按服务名动态查询）；密码含 `@` 的连接串兼容处理（sysdba 兜底）。
- **金仓 V8/V9 差异自适应**：系统目录（sys_database/pg_database）、密码环境变量（KINGBASE_PASSWORD）、`||` 运算符方言等差异自动探测与适配。
- **openGauss 特有约束适配**：sha256 认证不读 PGPASSWORD（-W 显式传密码）、gs_dump 进度输出与数据流分离、-X fetch 替代 -X stream 等 7 项真机实测修复。
- **Redis 3.2–7 分代兼容**：REDISCLI_AUTH 仅 ≥6 生效，按探测版本自动分流。
- **SQL 产物新版本兼容**：新版 pg_dump 头部元命令（\restrict 等）自动剥离，保证旧服务器可导入。
- **my.cnf/默认凭据毒规避**：凡使用 MYSQL_PWD 的通道统一 `--no-defaults`，杜绝平台机残留凭据干扰。
- **操作系统兼容**：CentOS 7、openEuler、麒麟 V10 实测通过；Windows（OpenSSH）文件备份与 SQL Server 通道实测通过；x86_64/aarch64 ELF 架构推送前预检。

## 4. 备份能力

### 4.1 备份类型与模式

- **全量**：逻辑（单表/单库/全实例逐库打包 + manifest.json）/ 物理（数据库原生工具）。
- **增量**：MySQL XtraBackup LSN 真增量（全量→增量链恢复自动合并，✅ 双层链真机验证）；Oracle RMAN 双通道——INCREMENTAL→Level 0 基备 / DIFFERENTIAL→**Level 1 差异真增量**（171 19c 实测：L0 2.06G 352s → L1 1.9MB 37s，L0+L1 链经 RESTORE VALIDATE 真实校验含抽取数据文件硬证据）；文件增量（指纹比对）；组合任务（全量+增量自动编排调度）。
- **日志备份**：MySQL 备份后 PURGE binlog（可配置保留窗）；Oracle 归档触发条件（归档个数/FRA 空间阈值）。
- **自定义脚本备份**：任意数据库类型可注入自定义脚本（平台注入连接信息/产物目录环境变量，SSH 通道执行，产物自动拉回并登记 size/sha256，✅ 本机+SSH 双通道真机）。

### 4.4 文件实时同步（core/file_sync.py）

面向「源 → 平台」的文件级持续保护（推送式实时同步，零 Agent、零 inotify 依赖）：

- SSH **只读指纹扫描**（find + sha256sum + stat，零临时文件）→ sha+size 指纹 diff → 仅 SFTP 拉取变更文件；
- 版本化落地：`file_sync/<任务>/<时间戳>/`（多源 basename 冲突回退全路径展开），`keep_versions` 自动清理旧版本；删除以 `.deleted.txt` 记录（可回放）；
- sha256 逐文件对账；首轮无基线 = 全量；调度 30s 轮询 + 任务级 interval 节流，进程内运行护栏防双开；
- E2E 12/12（真实 SSH 目录全链路）。

**诚实边界**：轮询间隔内多次改写只保留最后状态；文件级粒度（大文件内部小改动整文件重传）。

### 4.5 虚拟机备份（core/vm/）

统一编排 + 四平台 Provider（全部走宿主机自带工具 + SSH/SFTP，**零 Agent、无需 vCenter/PBS 授权**，与离线交付约束一致）：

| 平台 | 全量 | 增量 | 一致性 |
|---|---|---|---|
| VMware ESXi | vim-cmd 快照 → 数据盘导出流式拉回 | ⚠️ 依赖快照链（无 CBT/VDDK，增量语义以快照差为准） | 快照 quiesce（依赖 VMware Tools） |
| Hyper-V | Checkpoint-VM → Export-VM → tar.exe 打包拉回 | ⚠️ 导出型（无 CBT） | Checkpoint（依赖集成服务） |
| KVM/libvirt | 外部快照（disk-only+atomic）→ qemu-img convert 冻结基盘 → blockcommit 回合并，**业务不停机** | ✅ **真增量**：virsh checkpoint dirty bitmap + backup-begin 只导出脏块（稀疏 qcow2），增量链 rebase 展平恢复 | domfsfreeze（依赖 qemu-ga） |
| Proxmox VE | vzdump（mode=snapshot，QEMU 内建快照）经 REST API 触发 → SFTP 拉回 | 仅 PBS 目标为真增量，否则全量（**如实标注**） | QEMU 快照 |

平台编排能力（复用调度/记录/告警体系，虚拟机作为一等受保护对象）：

- **纳管 → 发现 → 保护**：hypervisor 纳管（SSH/API Token 双认证）→ VM 发现 → 保护策略（合并调度、保留策略）；
- **恢复点（journal）**：快照链落账、`resolve_chain` 链组装、按时间 `find_rp_by_time` 定位恢复点；
- **恢复**：原位恢复（restore_in_place，ESXi 重新注册/Import-VM/virsh define）、**从恢复点克隆新 VM**（不影响生产）；
- **恢复点验证**：平台健康检查（TCP/ICMP）+ 心跳等待 + 产物校验；
- **合成全量**：从增量链合成新全量基线（控制链长）；
- **RPO / 保护计划报告**：按保护策略输出 RPO 合规与覆盖报告。

**诚实边界（如实）**：四平台通道已接入并具完整编排，**未做大规模真机验证**（现场首用请先在测试 VM 上跑一轮备份+恢复演练）；ESXi/Hyper-V 无 CBT 级增量，增量语义以快照/导出差为准（libvirt 为真增量）。

## 5. 恢复能力

> 多负载恢复入口：数据库恢复见本节；**文件恢复**（整包/跨主机/镜像树直接使用）见 4.3；**虚拟机恢复**（原位恢复/从恢复点克隆）见 4.5；CDP 任意时点恢复见 6.1；对象存储整桶/对象级恢复走对象存储页通道（✅ 逐对象 SHA256 硬核对实测）。

- **异名库/异机恢复**：恢复到任意目标实例/目标库名（源库零扰动，✅ 全库型实测硬核对）。
- **跨主机恢复**：目标为纳管 SSH 主机时自动推送产物远端恢复（含建库、目录准备）。
- **单表/逻辑表直接恢复**：MySQL 全实例 tar 表锚点切片（头部净化防误灌回源库）；Oracle impdp TABLES；PG pg_restore --table；达梦 dimp TABLES（✅ 全真机）。

- **恢复前自动预检闸**（所有恢复入口统一继承）：产物存在/SHA256 基线/结构嗅探/目标通道/恢复工具/解包空间，fail 级阻断且不落恢复记录，warn 放行并留审计；可全局开关。

## 6. CDP 持续数据保护与容灾

### 6.1 CDP 持续数据保护（数据库日志级）

AIDBM 的 CDP 定位为**日志级持续数据保护（准 CDP / near-CDP）**：捕获数据库日志流、持续封段落账恢复点，RPO 从「备份间隔」量级进入**秒~分钟级**；配合任意时点恢复（PITR），误删除/逻辑损坏可回滚到事故前任意一刻。与卷级/字节级 CDP 的边界见第 13 章（内核驱动类明确不做）。

| 环节 | 能力 |
|---|---|
| 日志捕获（CDC） | MySQL binlog（--stop-never 持续拉流）、PG/金仓 WAL 流接收（复制槽 + pg_receivewal）、Oracle LogMiner（含 XID 事务聚合）、达梦 DM_LOGMNR |
| 守护与自愈 | 守护进程托管（RT supervisor）、健康灯（degraded=低流量无新段的 RPO 监控口径）、位点越界自动回退当前位点（防 binlog 轮转 1236 崩溃）、重启断点续接 |
| 封段与恢复点 | trigger / force_seal 主动封段（各库型方言适配：FLUSH BINARY LOGS / pg_switch_wal / ARCHIVE LOG CURRENT / SWITCH LOGFILE），恢复点 journal 落账（重启不丢） |
| 任意时点恢复 | `/api/rt/preview` 恢复计划 → 恢复到中间时点 / 最新（跨段链式回放，✅ 13 项闭环实测：A 批次在、B 批次不在的硬核对）；MySQL binlog 多段链 + stop-position/datetime 精确截断 + **GTID 模式双路径**（保留/剥离，恢复库可作 GTID 复制源） |
| 事务级精准还原 | Oracle LogMiner：捕获段浏览 → 按 XID 聚合事务时间轴 → SCN 逆序 undo 反向回滚计划 → 验证码双闸执行（✅ 真机 19c） |
| RPO 目标驱动 | 保护目标（rpo_target_min）联动检查：近实时目标未开 CDP 如实判 fail；备份间隔超出 RPO 目标告警（只评估不自动改配置） |
| 仿真防线 | CDC 仿真通道默认禁用；能力不足（引擎/客户端缺失）start() 恒失败置 FAILED，**绝不静默降级产假数据**；SQL Server 无 CDC 如实拒绝 |

### 6.2 容灾

- **容灾切换（failover/failback）**：三步法（探测→fencing 冻结旧主→提升备库→DNS 牵引）；GTID 分叉检测（分叉时如实拒绝自动回切，防丢数据）；DNS 解析回读验证；**RTO 实测 15–17 秒**；切换历史逐步留痕。
- **两步可拆切换**：业务切换（主备互换）与 DNS 牵引两个阶段可一次执行也可拆分（仅业务 / 仅 DNS 补偿），切换前后承载环境与 DNS 配置在界面可视化。
- **容灾总览**：站点地图（按链路配置的城市经纬度定位，生产 ■ / 容灾 ▲ / 数据复制流动画）、容灾业务清单与地图联动下钻、当前承载环境实时展示。
- **容灾巡检**：环境健康（生产/容灾可达）+ 数据复制状态（IO/SQL/延迟）+ DNS 运行状态三块定时/手动巡检，报表导出 CSV/Excel。
- **容灾切换（failover/failback）**：三步法（探测→fencing 冻结旧主→提升备库→DNS 牵引）；GTID 分叉检测（分叉时如实拒绝自动回切，防丢数据）；DNS 解析回读验证；**RTO 实测 15–17 秒**；切换历史逐步留痕。
- **容灾切换演练（switch drill）**：主库健康前提下的**计划性切换**闭环——预检（主备可达+复制健康）→ 旧主写入冻结 → 等待备库 GTID 追平（**追不平绝不提升，RPO=0**）→ 提升换主 → DNS 牵引+解析回读 → **新主写入探针**（真实写路径验证）→ 旧主转从追平 → 自动回切（现主冻结→追平→提升原主→**探针数据闭环核对**→降级现主→DNS 切回→探针清理→拓扑终态核对）。全程 RTO 分段计时与评分（**实测切换 15.0s / 回切 17.5s，连续 4 轮演练全绿**），演练结束自动恢复原拓扑、探针库零残留；演练失败如实中止并返回已执行步骤+当前健康快照供人工介入。当前支持 MySQL/MariaDB 主备链路。
- **自动切换策略**：连续探测失败自动触发切换（可人工确认门），监控状态持久化、告警去重。
- **真实恢复演练**：真恢复到临时隔离库 → 逐表行数校验 → 评分（100 分制，含 RPO 阈值）→ 自动销毁，演练库零残留（✅ MySQL/MariaDB；其他库型引导走恢复校验通道）。
- **两地三中心（池复制）**：存储池链式复制编排（serial/parallel、站点角色 production/同 城/异地、重试策略），备份成功自动触发，副本分布视图与逐站日志，支持取回（fetch back）。
- **架构依赖说明（如实）**：切换/演练依赖 MySQL GTID 复制与 DNS（dnsmasq）提供方；数据库服务器 systemd 服务配置错误（如 PIDFile 指向错误导致周期性 kill-loop）会被演练如实暴露——本轮已修复 171 侧此类环境缺陷。PG 系主备切换通道待 PG 同大版本主备环境恢复后验证（当前测试环境 171 的 PG16 备库已停用、替换为 PG18 独立实例，物理流复制不支持跨大版本，如实不具备验证条件）。

## 13. 能力边界与不承诺清单（如实）

**未实现 / 未完成（有需求请立项评估）：**

1. 元数据库分布式/HA 与调度器多活（当前单进程 APScheduler，SQLite/PG 单点）；大规模集群部署场景需评估。
2. Oracle RMAN Level 1 真增量已实现并真机验证（DIFFERENTIAL→L1，171 19c 实测 L0+L1 链校验通过）；INCREMENTAL 语义保持 Level 0 基备。
3. MySQL GTID 模式 PITR 已实现并真机验证（目标 GTID 就绪自动保留/不就绪自动剥离，双路径 18/18）；恢复库可直接作为 GTID 复制源。
4. Runbook 恢复编排已实现（v2.4.2）：8 类步骤（备份/恢复/行数校验/等待/通知/容灾切换/回切/测试克隆）串成可复用剧本，一键执行、RTO 计时、高危步骤审批闸（1 小时超时如实失败）、失败中止/放行策略；页面 /runbook。边界：步骤级审批需人工放行（无自动回退引擎），「失败自动回切」可用 failback 步骤显式编排但不自动触发。
5. 三员管理（涉密分立）、多租户、SNMP 告警上报未实现。
6. 病毒查杀/EDR 不做（离线无病毒库，安全检测为启发式）。
7. 卷级 CDP（内核驱动）、裸机恢复（BMR）/P2V、VDisk 挂载即时恢复不做（与零 Agent 架构冲突，明确不跟随）。
8. NDMP/HDFS/Exchange/Domino/DB2/Informix/HANA/Caché 等小众负载未支持。
9. MongoDB oplog 时间点恢复、Redis AOF 实时未实现。
10. 虚拟机备份（ESXi/Hyper-V/libvirt/PVE 四平台）编排+恢复点+克隆/验证/报告已完整实现，未做大规模真机验证；ESXi/Hyper-V 无 CBT 级增量（增量语义以快照/导出差为准，libvirt 为 dirty bitmap 真增量）。
11. SQL Server 无 CDC 实时备份（无对应引擎，如实不支持，不做仿真降级）；TiDB/OceanBase 物理备份按分布式架构不适配 xtrabackup 如实拒绝。

**已实现但未真机验证（现场首用请先跑预检+小库备份）：**

21. 瀚高/优炫/TiDB/OceanBase 为协议兼容层接入（复用 PG/MySQL 引擎），未在真实实例上全量验证；TiDB/OceanBase 物理备份如实拒绝。
22. 元数据库 MySQL 后端未真机验证（PG 后端已实测）。
23. NAS（群晖 DSM）通道未真机验证。
24. SQL Server 物理备份（SSH 通道）在 Windows 目标机需要 OpenSSH，未在全部 Windows 版本上验证。

**架构性边界（如实告知）：**

25.  应用层不可变防护可防平台自身与凭据泄露、防普通误删（chmod）；**物理级不可变需文件系统 immutability/S3 Object Lock 支持**，不支持时显式报告。
26.  CDC 覆盖 MySQL/PG/金仓/Oracle/达梦五系；**SQL Server 无 CDC，任务会如实报"不支持"**，不降级仿真。
27.  逻辑增量备份（PG 系）如实回退全量并附说明（pg_dump 无原生增量）。
28.  文件实时同步为指纹轮询（默认 30s，文件级粒度），轮询间隔内多次改写只保留最后状态。
29.  异构库型校验和不可比（各引擎哈希算法互异），自动降级为行数+抽样+PK 归并并如实标注。
30.  平台跨数据库服务器 SSH 为主通道；数据库服务器上不装任何工具是硬约束——部分深度能力（如 RMAN）依赖目标库自带工具，客户端缺失时如实报错。
