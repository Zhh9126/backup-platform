## 二、不可变备份四层防护（G13 闭环）

对标 Veeam/Commvault 的 Immutability 能力，防止备份被误删或被入侵者清空：

| 层 | 机制 | 说明 |
|---|---|---|
| 1 保留锁定 | `POST /api/records/<id>/lock`（days，0=永久）/ `/unlock`（reason 必填） | 只许延长不许缩短；重复加锁取更晚到期；幽灵记录/失败备份/演示记录拒绝锁定；解锁强制写审计原因（WARNING 日志） |
| 2 产物写保护 | 锁定时 chmod 去写位（0o555） | 失败如实标记 `write_protected=0` 不静默；解锁恢复 |
| 3 完整性基线 | sha256 基线 + 每日复检任务（`backup_integrity_check`，默认 04:40，cron 可配） | 漂移记 ERROR 日志；`/verify-integrity` 手动触发 |
| 4 删除路径拦截 | 定期清理 / GFS 生命周期 / 分层下沉 / 任务删除四路全部跳过锁定记录 | 计划与执行间新加的锁也有第二道硬护栏 |

- 数据模型：`backup_records` 新增 locked / locked_at / retention_until / write_protected / checksum_verified_at / checksum_ok / lock_note 七列
- 任务侧：`extra_options.retention_lock_days>0` 时备份成功自动上锁
- 验证：`tests/test_immutability.py` 14 条全过；九文件组合回归 115 passed
- **诚实边界**：应用层锁防平台自身误删与凭据泄露场景；chmod 防普通误删（root 仍可强删）；物理级不可变需文件系统 immutability 或 S3 Object Lock，当前不支持时显式报告

## 三、同步 / 迁移可靠性三轮优化（"不重不丢不错"）

**实时同步（轮询 CDC）**：

- **水位持久化**：从 message 文本改存 `sync_tasks.realtime_watermark`（JSON `{col,value}`），写入成功后才推水位；**重启续传**：列名匹配则跳过全量快照直接续传（此前每次重启重做全量）
- **回看窗口** `poll_overlap_seconds`（默认 0）：时间戳水位回拨 N 秒重叠读取，upsert 幂等吸收，消除同秒边界丢数（仅对可解析时间戳生效，数值水位不回拨）
- **周期对账** `reconcile_every_polls`（默认 720 轮）：源/目标行数比对，检测轮询模式天然漏掉的 DELETE，差异写入任务 message
- **批次写入失败**：非 append 模式 rollback 后自动重试 1 次（append 无唯一键保护不自动重试，防重复）；错误明细（表名+原因+批行数，最多 20 条）进 error_details
- **数量守恒对账**：`sync_records` 新增 read_rows / error_rows / watermark 三列，读取=写入+失败
- 修复存量 P0：`core/sync.py` 死文件被 `core/sync/` 包遮蔽，调度器 cron 触发的同步任务此前 100% 静默失败（AttributeError）

**迁移（一站式计划）**：

- **dry-run 预演**：`POST /migration-plans/<id>/dry-run`，7 库型源表清单预检，不动目标库
- **逐表 manifest**：migrate 阶段逐表状态/行数/错误明细落盘
- **断点续跑**：failed + manifest 自动 resume，已完成表自动跳过；append 模式失败表先清空目标防重复
- **校验升级**：行数比对 + **抽样内容比对**（`verify_sample_rows` 默认 100，0=关；bool→1/0 归一防 tinyint(1) 误报；内容不一致→表 match=False 且 verify 不通过）
- **MySQL→达梦兼容顾问补齐**：静态 SQL 清单六条（CONCAT NULL / IFNULL→NVL / LISTAGG / DATEDIFF 带单位 / LIMIT→ROWNUM / 隔离级别）、列级保留字交叉比对、迁移成功后自动 `SP_TAB_STAT_INIT` 逐表收集统计

验证：`test_sync_reliability` 17 条 + `test_dm_compat` 9 条；E2E 注入瞬时故障部分写入 → failed → 续跑 completed，目标库行数无重复。

## 五、数据库 OS 用户标准变量（环境差异变量化）

**背景**：客户环境里数据库软件的安装属主用户可能与默认不同（Oracle 不叫 `oracle`、达梦不叫 `dmdba`、openGauss 不叫 `omm`）。此前 `su - oracle` 等写死在各引擎中，环境不匹配即整链路失效。

**设计**：流程保持标准不变，把「在哪个 OS 用户下执行」收敛为标准变量，三级覆盖链：

```
任务 extra_options.db_os_user  >  纳管主机 ssh_hosts.db_os_user  >  库型默认
```

- 库型默认表：oracle→oracle、dameng→dmdba、opengauss/panwei→omm、kingbase→kingbase、postgresql→postgres、mysql/mariadb→mysql
- 数据模型：`ssh_hosts` 新增 `db_os_user` 列（建表 + 存量库自动迁移）
- 落地范围：`base._resolve_check_user()` 统一入口；Oracle 9 处、达梦全部写死点（su/chown/home 路径/6 处 check_user）、openGauss 3 处、跨主机恢复脚本、Oracle schema 克隆全部接入
- 前端：主机纳管表单与备份任务高级选项各新增「数据库 OS 用户」输入框，编辑回显
- 验证：`tests/test_db_os_user.py` 12 条（优先级链 / JSON extra 兼容 / 主机字段落库往返 / 引擎集成 / 禁止回退写死的静态契约）

**使用**：某台服务器安装用户非默认 → 纳管主机填一次全局生效；单任务临时差异 → 任务高级选项覆盖；不填则完全兼容旧行为。

首轮 20/28，暴露并修复 3 个工具解析缺陷：

1. **本机物理备份预检误报**：`_ensure_local_clients_on_path` 的兜底 glob 只扫 `/opt` 两级，漏掉 `/pgdb/pgsql/bin` 等自定义根目录。修复：终极兜底接入 `_resolve_local_tool`（宽目录枚举 + `--version` 版本择优）。

3. **达梦恢复 rc=127**：`_restore_logical_remote` 解析出了 `dimp_bin` 绝对路径却硬编码裸 `dimp`。修复：使用解析值。

## 七、达梦 dimp 恢复语义：存量表覆盖（TABLE_EXISTS_ACTION=REPLACE）

- **现象**：目标 schema 存在与备份同名表时，dimp 默认整表 fail（rc=2），137 SYSDBA 存量测试表触发
- **修复**：远程 dimp / 本机 dimp / cross_host DM 恢复脚本三处统一加 `TABLE_EXISTS_ACTION=REPLACE`（与 Oracle impdp 语义对齐）
- **实测教训（重要）**：**不能加 `IGNORE=Y`**——它让 dimp 在表已存在时跳过重建直接插数据，触发 `-6602` 唯一约束冲突，与 REPLACE 语义互斥。加 IGNORE=Y 后 rc=2，去掉后 23 张表全部导入成功。已写入代码注释与静态契约（测试禁止回加）

```bash
# 1. 在有网机器导出（已提供现成包则跳过）
docker save ghcr.io/zhh9126/backup-platform:v1.4.17 -o aidbm-v1.4.17.tar

# 2. 拷贝到内网机器后导入（gzip 包 docker load 直接支持，无需先解压）

docker run -d --name backup-platform \
  -p 8080:8080 \
  -v backup-data:/data \
  -e BACKUP_ROOT=/data/backups \
  --restart unless-stopped \
  ghcr.io/zhh9126/backup-platform:v1.4.17
```

### 部署后初始化

1. 浏览器访问 `http://<服务器IP>:8080`，默认账号 `admin / admin123`（**首登强制改密**）
2. 「系统设置 → SSH 主机」纳管数据库服务器（或任务级 SSH 凭据）——备份任务执行的前置条件
3. 新建备份任务（连接 / 备份类型 / 调度 / 保留策略），运行前平台自动做产物级校验
4. 多人协作：在「用户管理」分配角色（admin / operator / viewer），菜单按权限自动收敛
5. 中英文切换：页面右上角「中文 / English」按钮，选择自动记忆
6. AI 助手（仅 AI 版镜像）：侧边栏「AI 智能助手」，自然语言查询任务/记录/存储并驱动操作；LLM 不可达时自动本地规则兜底

### 离线环境注意事项

- 运行时**零联网**：全部依赖（Python 驱动 / JDBC+JRE / xtrabackup / PG 客户端 / 达梦 dmPython）随镜像自带，部署后可运行 `python tools/check_env.py` 自检
- `/data` 必须挂载持久化卷，否则备份写进容器可写层，重建容器即丢失
- 被管理的数据库服务器**不安装任何东西**（零安装原则），备份经 SSH 使用数据库自带工具，或由平台临时推送二进制（执行后清理）
- 完整清单见 [feature_manifest](docs/feature_manifest_20260917.md)，离线运维手册见 [offline_ops_manual](docs/offline_ops_manual_20260917.md)
