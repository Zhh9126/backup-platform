## 部署引擎三大修复（PATH 不生效 + 日志误报 + 多版本兼容）

### 1. 部署日志不再误标 "ERR:"
原 `_run_ssh` 把 stderr 全部行加 `ERR:` 前缀，但 MySQL/PG/Redis 的 info/warning 也写 stderr（如"Using a password...insecure"），导致日志全红。改用 `_is_real_error(s)` 智能判断：
- 含 `[ERROR]` 且带 `[MY-...]`（MySQL 真实错误）→ 标 ERR
- 含 `FATAL` 且含 `ERROR` → 标 ERR
- 其他（warning/info/system/systemLog）→ 不加 ERR，直接显示

### 2. PATH 持久化（/etc/profile.d/）
所有 7 种数据库的安装脚本末尾都写入 `/etc/profile.d/<db>.sh`，包含：
- `export <DB>_HOME=<base>`
- `export PATH=$<DB>_HOME/bin:$PATH`（Oracle/Kingbase/DM 还加 `LD_LIBRARY_PATH`）
- `chmod 644` 生效
- 末行提示「`source /etc/profile` 或重新登录」
- 加 `ldconfig` 刷新动态库缓存

### 3. 多版本兼容
- **MySQL 5.6 vs 5.7+ 自动检测**：优先用 `mysqld --initialize-insecure`（5.7/8.0/9.x），回退 `mysql_install_db`（5.6 及更早）
- **Oracle 11g/12c/19c/21c 自动定位 ORACLE_HOME**：`{base}/product/{19c|21c|12.2.0|11.2.0}/dbhome_1` 按版本分支查找
- **PG 14+ 兼容**：自动从 `/usr/lib/postgresql/*/bin/initdb` 找发行版 initdb
- **MySQL 客户端密码**：`/root/.my.cnf` + `mysql_config_editor` 风格的免密客户端
- **DM 自动运行 dminit**：根据安装包类型（iso/bin/普通）找 `DMInstall.bin` 后尝试 dminit 初始化
- **Kingbase 兼容两种 ALTER USER 语法**：`WITH PASSWORD` vs 旧版
- **Redis `MALLOC=libc` 编译参数**：避免 jemalloc 依赖
- **MongoDB 自动找 mongod/mongosh**：兼容非默认位置

### 测试：30/30 PASS
- 7 种 DB 脚本都含 /etc/profile.d/、export PATH、DEPLOY_OK（21 项）
- MySQL 含版本检测/.my.cnf/ldconfig/source 提示（5 项）
- `_is_real_error` 智能判断 4 项（识别真错误、不误标 warning/system/FATAL）
