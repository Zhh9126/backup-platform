## 恢复中心

/restore 统一展示数据库、文件/NAS、对象存储（包括 OBS）、虚拟机四类恢复点。
服务端分页和搜索，排除失败及仿真记录；虚拟机使用独立恢复点目录，避免与普通记录 ID 混用。
按备份时的实际物理/逻辑方式恢复，不因后续修改任务配置而误选引擎。
对象恢复支持选择另一个已纳管对象连接，源端和目标端凭据各自保留；缺省不覆盖目标对象。
修复对象 HEAD 权限错误被当作不存在、if_newer 覆盖较新对象、恢复暂存目录并发冲突，以及产物成员校验。
记录目标桶/前缀用于恢复历史。NAS 本地解包与推送回 NAS 明确区分。
虚拟机恢复采用原生恢复/新建克隆入口、默认网络隔离；202 表示作业已受理，完成状态来自作业轮询。
恢复提交前展示实际来源与目标并保留平台恢复安全门。

## 数据库实时保护

恢复点序号分配与 object_key 幂等登记放到同一数据库事务中。
SQLite 使用 BEGIN IMMEDIATE；PG/MySQL 分支使用任务父行 FOR UPDATE 串行化（本轮未连接外部元数据库实测）。
幂等重试不再用缺省字段清除已有 verified、storage_tier 等元数据。
封存日志入账失败保留待重试队列，下一轮先重试旧段，失败处停止发布后续段，避免父链越过未入账段。
登记前重算 SHA256；封存段损坏阻止发布后续恢复点。重复提交不重复计入捕获统计。
续传状态原子替换失败时保留上一份有效状态，并在发布临时文件前 fsync。
这些测试不等同于 MySQL/PG/Oracle 等实际日志流及时间点恢复验收；没有真实数据库实例的组合仍待接入验证。

## 克隆服务

创建资源、销毁、到期回收、校验和快照变更使用每申请独立的可续期租约，阻止多进程交叉操作。
超过 45 分钟但仍持有执行租约的创建任务不会被列表清理误标失败。
过期回收不处理 creating；清理失联 creating 使用状态/更新时间 CAS。
逻辑克隆预检核对已有 SHA256 基线，损坏产物拒绝创建。
保留无 Agent 默认方式，以及已有各数据库专用隔离运行时的能力边界。

## VM 数据完整性追加修复

本地真实测试明确区分热快照的崩溃一致性与正常关机后的文件系统一致性；未刷盘的测试文件不能作为已落盘数据。追加检查发现并修复：
- 虚拟机备份下载后独立核对实际文件大小和 SHA256，空文件、截断或校验值不一致不登记成功恢复点。
- 恢复/克隆/验证回推前校验完整链；本地副本缺失时不盲信历史远端临时路径。
- 回推中途失败回收已推送的临时副本；平台原件保留。
- 自动验证不再使用已经清理的源端临时产物，而是从本地完整备份链回推，并在验证后清理。
- 不支持或实际低于请求的一致性等级明确失败；不会把 crash 备份宣称为 fs/app。
- 归档文件名规范化并增加随机后缀，避免 VM 名称中的目录分隔符及同秒重名。
- build/integration-20261120/vm-integrity-final2.log：44 passed（含恢复中心与 VM 编排/完整性）；这仍是离线契约回归，不等同于本地 Workstation 实机验收。
