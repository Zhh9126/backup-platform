## 四、备份/恢复预检（Precheck）

**备份预检**（备份任务行「预检」按钮）——发起备份前逐项探测：任务配置完整性 / SSH 通道连通 / **源库原生直连**（凭据错误当场暴露）/ 备份工具就绪（复用引擎 preflight：本机 PATH + 远端 su 探测 + 自带插件）/ 物理模式归档提示 / 平台存储空间。

**恢复预检**（备份记录行「恢复预检」按钮）——产物存在非空（0B 直接阻断）/ **sha256 基线比对**（篡改/损坏当场暴露）/ 结构探测 / 恢复目标 SSH 可达 / 按库型恢复工具（sys_restore+ksql、gs_restore、dimp、impdp、psql、mysql，远端按 OS 用户探测）/ 可选目标库连通 / 解包临时空间。

**诚实边界**：预检是**探测不是演练**（不落盘产物、不写目标库）；通过代表当前配置的已知前置条件均满足，不保证中途网络/磁盘故障不发生。

**真环境 E2E 5/5**：MySQL 本机备份预检全 pass / 达梦 137 SSH 备份预检全 pass / 成功记录恢复预检全 pass / **篡改 checksum → 恢复预检 fail（integrity 阻断）** / 达梦远端恢复预检全 pass。

## 五、数据对比深度测试与 3 个真缺陷修复（2026-10-15）

**E2E 8/8 全通（137 真机）**：MySQL↔MySQL 一致（checksum 相等）、MySQL↔达梦一致/差异检出（改 1 删 1 → mismatch 明细「行数不一致(3≠2)；主键归并发现 3 处差异」）、MySQL↔金仓抽样一致、报告落库。

**修复的 3 个真缺陷**：

1. **建表缺列**：`data_compare_tasks` schema 缺 `force_pk_compare/chunk_rows/chunk_threshold` 三列（models 字段集有、建表 DDL 没有）——**全新部署创建对比任务必炸 no such column**；两处建表 DDL 补列 + init_schema 自动迁移（已有库 ALTER ADD COLUMN）。
2. **datetime 归一化不一致**：此前 `isoformat(sep='T')`，与部分驱动返回的字符串时间（空格分隔）不一致 → 异构对比时间列全部误报差异（实测 sample_diffs 源 `2026-10-15T10:00:01` 目标 `2026-10-15 10:00:01`）。datetime 统一 `strftime('%Y-%m-%d %H:%M:%S')`（含微秒），字符串时间 T→空格归一。
3. **checksum 两处**：① 达梦 `ORA_HASH` 不可用（COMPATIBLE_MODE 非 Oracle 实例，实测 CODE:-2207 Member access [ORA_HASH] unresolved）→ 改 MD5 前 8 位转数值求和；② **异构库型直接比 checksum 数值必然不等**（CRC32/hashtext/ORA_HASH/MD5 算法互异）→ 仅同库型比较，异构一致性由行数 + 抽样/主键归并判定。

**顺手抽测巡检** ✓：真连库完整巡检（连通性 ok / 调度 warn / 上次运行 ok 三项真实检查）。
