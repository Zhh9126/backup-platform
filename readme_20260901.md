## 三、使用方式（数据库服务器无需安装任何客户端/Agent）

平台的三条铁律：

1. **平台侧零依赖**：不装数据库客户端、不需要 Java、不配置任何环境变量；
2. **数据库服务器零额外安装**：备份直接使用**数据库自带的备份命令**
   （mysqldump / pg_dump / sys_dump / expdp / rman / dexp / sqlcmd 等，
   均随数据库软件自带），平台通过 SSH 自动发现工具路径
   （运行进程 / `/proc` / 常见目录 / 包管理器多级探测）；
3. **唯一需要做的**：在任务里填数据库连接信息，并（推荐）勾选
   「数据库服务器 SSH 执行通道」直接填 SSH 账号——**无需预先纳管主机**。

使用步骤（以 MySQL 为例，其余数据库同理）：

1. 新建任务：选数据库类型、填 IP/端口/账号密码、库名（留空 = 全实例）；
2. 「高级」页勾选 **SSH 执行通道**，填数据库服务器的 SSH 账号（默认同机）；
3. 保存并立即执行 → 平台 SSH 到数据库服务器自动发现备份命令并执行，
   产物经 SFTP 拉回平台落盘（真实 size + SHA256）；
4. 恢复：备份记录一键恢复（自动推送产物到服务器执行原生恢复命令）。

> 极端场景兜底：若工具安装在极冷门目录导致自动发现失败，任务「高级」页的
> 「备份命令所在目录」（tool_path）手动填写即可，作为 PATH 前缀参与探测与执行。

## 四、今日新增与优化明细

### 1. 原生直连，去掉 Java 依赖
- 新增 `core/native_conn.py`：连接测试 / 拉库列表 / 数据对比全部改用
  纯 Python 驱动（pymysql / psycopg2 / oracledb 瘦客户端 / dmPython），
  **不再需要 JDK/JRE**；JDBC 降级为可选兜底
- Docker 镜像按需内置 JRE + JDBC 驱动 jar（仅 Oracle 11g 等兜底场景使用）

### 2. SQL Server 备份/恢复（新增，Linux + Windows）
- 严格按微软官方 T-SQL：
  `BACKUP DATABASE ... WITH COMPRESSION, CHECKSUM`、
  差异 `WITH DIFFERENTIAL`、日志 `BACKUP LOG`、
  还原 `RESTORE FILELISTONLY` + `RESTORE DATABASE WITH MOVE, REPLACE, RECOVERY`、
  校验 `RESTORE VERIFYONLY WITH CHECKSUM`
- sqlcmd 经 SSH 在数据库服务器执行；密码走官方 `SQLCMDPASSWORD` 环境变量
- Windows 目标：`os_type=windows` 自动切换 cmd 语法

### 3. 全实例备份统一改造（PG / Kingbase / MySQL / MariaDB）
- 修复金仓/PG 报 `unrecognized option '--all-databases'`：全实例改为
  **枚举库 → 每库一个文件 → 打包 tar.gz + manifest.json**
  （PG 系附 `dumpall -g` 全局对象；MySQL 逐库 `--databases` SQL）
- **默认仅备份业务库（排除系统库）**，可勾选「包含系统库」
- 恢复端自动识别 tar 产物：恢复全局对象 → 缺失的库自动 CREATE → 逐库恢复
- 可选整实例 SQL 模式：`extra_options` 传 `{"all_db_mode": "dumpall"}`

### 4. 任务级 SSH 凭据（免纳管）
- 任务表单「高级」页勾选 SSH 执行通道直接填账号，**无需先纳管主机**
- 密码加密存储；编辑留空 = 不修改

### 5. 工具路径手动兜底（可选）
- 自动发现失败时，任务里填写备份命令所在目录（`tool_path`），
  作为 PATH 前缀注入远程 SSH 命令与本机回退执行，最高优先参与探测

### 6. Docker 镜像发布规范化
- tag 规则：`X.Y.Z`（纯版本）+ `X.Y.Z-YYYYMMDD`（版本+构建日期，推荐）
  + `latest` / `community` 滚动别名
- GHCR 国内加速器配置见上文

### 1. 多数据库同步与实时同步（7 库型）

- **同步插件补齐**：新增 Oracle（oracledb 瘦客户端）、达梦 DM8（dmPython，
  随离线包交付）、SQL Server（pymssql）；金仓复用 PG 协议——
  同步库型覆盖 mysql/mariadb/postgresql/oracle/dameng/sqlserver/kingbase 共 7 种
- **轮询式实时同步（polling CDC，离线默认）**：纯 Python 零外部组件——
  全量快照（upsert 幂等）→ 增量列 watermark 周期轮询 → upsert 目标端，
  断点续传（watermark 落任务 message）。Flink CDC 轨道保留为在线环境
  可选（flink_config.engine="flink" 显式开启）
- **跨机实测**：137 PG14 → 140 MySQL 轮询实时同步——全量快照 2 行，
  源端插入新行 2 秒内自动同步（watermark 3→4），优雅停止 ✅

### 2. 表级恢复标准化（M2 恢复向导）

- 备份完成后自动扫描产物对象清单（backup_objects 表）：MySQL dump 解析 /
  pg_restore -l / 达梦 dmp 二进制扫描
- 恢复请求支持 tables 参数：**只恢复勾选的表**
  - MySQL：dump 段落过滤（结构+数据）
  - PG：pg_restore --table
  - 达梦：dimp TABLES=
- API：GET /api/records/<id>/objects
- 实测：MySQL/PG 表级恢复——目标库仅含勾选表，行数一致 ✅

### 3. 磁带库 D2T 对接（对标 DBackup 2.11）

### 13. 数据迁移 vs 数据同步：概念区分（2026-09-06，联网调研落档）

调研来源：天翼云官方文档《数据迁移、同步和恢复的区别》、阿里云 DTS
（迁移=一次性/同步=持续）、AWS DMS（Full Load vs Ongoing Replication/CDC）。

**业界定义**：

| 维度 | 数据迁移（Migration） | 数据同步（Sync/Replication） |
|---|---|---|
| 任务性质 | **一次性任务**，存量数据批量搬迁，完成即止 | **持续性任务**，常驻运行保持两端一致 |
| 典型场景 | 上云、换库（异构）、数据中心搬迁 | 数据灾备/热备、异地多活、读写分离、实时数仓 |
| 关键指标 | 完整搬完、结构转换正确、一次性校验 | 延迟（秒级）、增量捕获（CDC）、断点续传 |
| 写入模式 | append/overwrite/upsert 皆可（**overwrite 仅此可用**） | append/upsert（**禁止 overwrite**——破坏一致性语义） |
| 结束态 | success/failed，跑完写记录、可校验 | 运行中/已停止，手动 start/stop |
| AWS DMS 对应 | Full Load | Ongoing Replication (CDC) |
| 阿里 DTS 对应 | 迁移任务 | 同步任务 |

**平台落地**：
- 术语：sync_mode=full 统一表述为"数据迁移（一次性全量）"，不再叫"全量同步"；
  incremental/realtime 表述为"数据同步（周期增量/实时 CDC）"
- 引擎约束：同步类任务（incremental/realtime）+ overwrite → 直接拒绝
  （概念冲突：持续性任务不支持覆盖写入）
- 预校验新增 task_kind 检查：明示任务性质；同步+overwrite 判 fail
- 前端联动：模式下拉明确"迁移/同步"；overwrite 选项仅迁移模式可选；
  任务列表列显示"迁移·一次性 / 同步·持续"

### 16. 异构类型映射引擎（2026-09-06，对标 DTS 结构初始化类型映射手册）

**调研来源**：阿里云 DTS 官方《结构初始化涉及的数据类型映射关系》
（MySQL→Oracle/ADB/ClickHouse 等完整映射表）、AWS DMS datatype mapping、
MySQL→PG 迁移实践。核心结论：**字段类型差异是异构迁移成功率的第一杀手**，
DTS 明言"源数据范围超出支持范围将导致目标写入精度降低"（静默降级）。

**新增 core/sync/type_matrix.py 映射引擎**：
1. 类型解析器：完整解析 base + 精度/刻度 + unsigned 修饰 + enum/set 值列表
   （修复 information_schema DATA_TYPE 丢失 unsigned/精度的问题，改用 COLUMN_TYPE）
2. 映射矩阵（依据 DTS 手册逐条落地）：
   - **UNSIGNED 升位**（最高风险）：INT UNSIGNED→BIGINT/NUMBER(10,0)、
     BIGINT UNSIGNED→DECIMAL(20,0)/NUMBER(20,0)（64 位无符号超有符号范围）
   - **精度**：DECIMAL(20,4)→NUMBER(20,4)；无精度 NUMBER→warn（溢出风险）
   - **时间**：DATETIME→TIMESTAMP(0) 降级提示；TIMESTAMP→Oracle LOCAL TIME ZONE
     时区审查；YEAR→INTEGER；TIME→Oracle **fail 不支持**
   - **特殊类型**：ENUM/SET→VARCHAR(128)（枚举约束丢失）；JSON→Oracle CLOB；
     BIT(n)→NUMBER；BOOLEAN→NUMBER(1,0)；UUID→CHAR(36)；
     GEOMETRY→**fail**（需 SDO 结构转换）
   - **自定义/未识别类型**→warn"按文本承载，人工确认"（绝不静默丢数据）
3. precheck 集成：overwrite 自动建表逐列输出**建表类型建议**（对标 DTS
   结构初始化），风险类型提示不拦截；append/upsert 模式实际目标类型
   与映射规则冲突时 warn/fail
4. check_column_mapping()：逐列映射评审报告（源类型→建议目标类型→风险→原因）

**实测**（MySQL 140 → 达梦 137 跨机，10 列风险类型表）：
- bigint unsigned → NUMBER(20,0) 升位 ✅ / int unsigned → NUMBER(10,0) ✅
- bit(1) → NUMBER(2,0) ✅ / datetime(3) → TIMESTAMP(3) 精度保留 ✅
- enum/set → VARCHAR(128) 枚举约束丢失提示 ✅ / json → CLOB ✅
- 20 用例矩阵回归全通过 ✅
