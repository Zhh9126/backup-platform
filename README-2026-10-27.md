# AIDBM 功能更新说明 · 2026-10-27

> 本期主题：**对标竞品补齐备份/恢复核心能力 + 三台真实主机全矩阵验证 + 国密 SM4 + 能力沉淀**。
> 涉及版本：aidbm:1.4.18（离线镜像已发布）。git：commit `82e604c`（main 分支）。

---

## 一、新增能力

### 1. 源端传输去重（文件备份 · 远程源）
- 远端只读清单（find+sha256sum+stat，零 Agent 零临时文件）→ 平台比对文件库 → 仅新/变文件走网络 → 平台侧重建标准 tar.gz（逐成员回读哈希硬核对）。
- **实测**：22MB 源、日变化 1 文件场景，第二轮实传 1.0MB，**带宽节省 95.5%**。
- 任务开关：文件备份表单「源端传输去重」；统计实时透出到备份消息（实传/逻辑/节省率）。
- 失败自动安全回退整包流式通道，正确性不受影响。

### 2. rsync 增量拉取（数据库物理备份单文件通道）
- 接收端持上一份产物作 basis，rsync 滚动校验只传差量，**免疫 gzip 偏移移位**。
- 改为**裸 tar 传输 + rsync -z 传输压缩**后实测：**实传 135–172KB / 逻辑 438MB（0.0%）**（一行 UPDATE 的差量）。
- 任务开关：`extra_options.rsync_delta_pull=1`；SSH 主机需密钥认证（本轮已全链打通密钥认证）；失败自动回退 sftp 整包通道。

### 3. 真实恢复演练闭环（对标"恢复演练"标配能力）
- drill 从元数据检查升级为：**真恢复到 drill_ 临时库 → 逐表行数校验 → 按结果评分 → 演练完自动销毁**。
- 复用生产恢复通道（进 backup_records 审计）；演练库 finally 兜底销毁；反例如实失败（无产物/不支持库型）。
- 排程支持 `real_mode`；前端演练类型与排程开关已接。当前支持 MySQL/MariaDB（库级隔离）。

### 4. 保护目标驱动收口
- RPO 目标近实时/≤5 分钟未开 CDP → **fail 级告警**；备份间隔 > RPO 目标 → warn；策略要求 cross_site 未配异地副本 → warn。
- 新增 `GET /api/protection-gaps`；首页「需要关注」列表直接呈现缺口项（可点击跳转任务）。

### 5. 国密 SM4（政企/金融招标硬指标）
- 备份产物加密新增 **SM4-128-GCM** 算法选项（GB/T 32907，与 AES-256-GCM 并列可选，v2 头带算法标识，v1 存量兼容）。
- **凭据存储升级**：密码等敏感字段从轻量混淆升级为 **SM4-GCM 高强度加密**（`sm4v1:` 格式），历史 `enc:` 混淆格式兼容读取。
- 任务配置 `extra_options.encrypt_algo="sm4"` 生效；消息标注算法。

### 6. 日志备份触发条件（对标白皮书显式卖点）
- MySQL：备份成功后自动 **PURGE 已覆盖 binlog**（`purge_binlog_after_backup` + `purge_binlog_keep_files` 保留窗口，幂等）。
- Oracle：归档日志备份**触发条件**（`archive_trigger`：未备份归档数阈值 / FRA 剩余空间阈值，SSH 真实探测，未满足如实跳过）。

### 7. 一键备份
- 任务页「一键备份」按钮：对全部启用任务逐个异步触发全量备份，返回逐任务受理结果。

### 8. E2E 测试矩阵沉淀（独立可复用能力）
- `scripts/e2e_matrix.py` + `tests/e2e/`：参数化多库型主机验收入口——纳管 SSH → 建任务 → 真实备份 → 产物校验 → PASS/FAIL 矩阵 + JSON 报告。
- 新库型/新主机接入 = hosts 清单加一个 target，一条命令回归。**这是发版标准验收入口。**

## 二、缺陷修复（本轮实测发现）

| # | 缺陷 | 影响 | 修复 |
|---|---|---|---|
| 1 | MySQL 增量链恢复中间层缺 `--apply-log-only` | 两层以上增量链第二层 apply 必失败 | 非最后一层全部补齐 |
| 2 | 本机通道增量基备只认全量 | 增量 2 永远基于全量，LSN 断链 | 基备含最近增量层 |
| 3 | 物理恢复 target_db 异名库不落地 | 恢复结果随临时实例销毁 | 恢复出的源库导出并灌入目标实例，表数校验 |
| 4 | Oracle PITR 备份片缺失（ORA-19505） | 物理备份拉回后远端零残留，PITR 无米下锅 | PITR 前自动**回推备份片 + CATALOG** |
| 5 | RMAN 脚本重复 connect（RMAN-06167） | PITR 直接失败 | 脚本去掉 connect target / |
| 6 | XtraBackup 推送缺库误报（OPENSSL_1.0.2） | 平台有 1.0.2k 却匹配不上 | 缺库查找加前缀 glob 匹配 |
| 7 | mysqldump GTID 报错（rc=2） | GTID 库部分库备份失败 | 自动加 `--set-gtid-purged=OFF` |
| 8 | mysqldump "Can't find file: 'event'" | mysql.event 缺失整任务失败 | 自动去 --events 重试 |
| 9 | 复制日志按钮 writeText 报错 | HTTP 环境剪贴板不可用 | 全局 copyText 降级助手 |
| 10 | 轮询实时同步增量循环 NameError（stop 未定义） | 所有轮询实时同步崩溃 | 补 get_stop_event 调用 |
| 11 | MySQL BIT 列同步整批失败（bytea↔smallint） | 含 BIT 列表同步失败 | 类型码 16→LONG + bytes 转整数 |
| 12 | API 创建任务传 dict 型 extra_options 500 | 外部自动化调用失败 | models 层 JSON 归一 |
| 13 | backup_type 误填备份模式值 500 | 运行接口 500 | 运行侧归一 + 创建侧 400 前置 |
| 14 | 侧栏菜单两列乱象 | Bootstrap nav 默认 wrap | flex-wrap:nowrap + 滚动记忆 |
| 15 | MySQL binlog 实时四项（log_bin 预检/手动封存失效/客户端解析/FLUSH my.cnf 毒） | 开启实时任务失败后置、手动触发无效 | 预检前置 + force_seal + --no-defaults |
| 16 | PITR 只回放单文件 / 不支持 zstd 产物 | 跨段恢复缺口 | 多段逐文件回放 + zstd 支持 + stop-position |

## 五、升级方式与已知边界

**升级**：目标主机 `docker load -i aidbm_1.4.18_offline.tar.gz` → 停旧容器 → 按原参数重建（/data 挂载卷数据不丢）→ 强刷浏览器（缓存戳 js=2026102603 / css=2026102602）。

**已知边界（诚实标注）**：
1. 真实恢复演练当前支持 MySQL/MariaDB（库级隔离），其他库型走恢复校验通道；
2. 129 的 MySQL 第二实例（23307）root 密码未知（23306 已用 123456 全链验证）；
3. rsync 恢复校验的远端推包环节遗留一个专项问题（传输与对账已验证）；
4. 凭据存储升级后**新写入为 SM4**，历史 `enc:` 记录兼容读取，如需全量迁移可执行一次凭据重录；
5. 提交推送需配置 gitee 部署密钥（本地 commit 已就绪）。
