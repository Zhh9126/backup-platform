# 全系统回归与并发优化验证记录

日期为 2026-11-20。开发和验证均在 Linux 服务器 192.168.109.128 的 /root/backup-platform-private 下进行。

## 验证结果

- 首轮全量回归共 1867 项，1797 项通过、62 项失败、8 项跳过。
- 修复后的全量回归共 1871 项，1806 项通过、57 项失败、8 项跳过。全量回归后又完成摘要格式修复及操作系统账号提示修复，并做定向复测。
- 并发、租约、配额、克隆抢占与接口权限等组合回归共 71 项通过。后续摘要、安全门和群晖恢复组合回归 45 项通过，1 项旧菜单文案断言未选入该组合。最终核心修复组合 41 项通过。
- 页面与 API 契约冒烟共 39 项通过。

## 本轮修复

- 调度租约改为带持有者和过期条件的原子更新，防止同时读到过期状态的多个实例都抢占成功。已过期租约无法直接续租。
- 备份并发许可共用活动任务集合，热修改并发上限不会生成第二套执行预算，降低上限时先等待现有任务释放许可。
- 克隆后台创建与审批增加数据库状态比较更新，多个审批请求只能启动一个执行器。
- 创建任务的配额检查和写入在同进程内共用写锁。SQLite 的 INSERT 同时包含配额条件，避免多个 Web 进程消耗最后一个名额。
- 新增 openpyxl 运行依赖，修复网络设备 Excel 模板接口的 500。测试环境补齐了所需 Python 驱动。
- 统一裸 SHA256 和 sha256: 前缀格式，修复群晖正常备份被误判为篡改、隔离并阻止恢复的问题。回归覆盖正常和篡改内容。
- 补齐容灾、剧本和巡检写接口的权限映射。
- 补充克隆页面英文词条，更新实际修改脚本的缓存戳，修正达梦启动提示中的固定操作系统账号。
- 压测工具改为使用传入的目标地址、校验登录结果、等待异步备份完成，并允许指定正确的资源采样 PID。线程中的未捕获异常会使压测失败。

## HTTP 并发压测

测试实例绑定 127.0.0.1:18080，使用独立的元数据库、备份和日志目录。客户端并发为 64，覆盖 386 条可直接访问的 GET 路径，包含 v1 别名。

| 阶段 | 请求数 | QPS | P95 毫秒 |
| --- | --- | --- | --- |
| 创建任务 | 60 | 172.8 | 280.5 |
| 执行备份 | 60 | 53.0 | 1020.7 |
| GET 接口 | 1158 | 258.6 | 508.7 |
| 混合读写 | 2140 | 207.4 | 604.0 |
| 写接口 | 120 | 351.1 | 88.7 |

60 个脚本备份全部成功并完成记录对账，18 项数据一致性检查通过。以上统计没有 5xx 或请求异常，接口探测包含缺少资源或入参时预期的 400/404。未对比相同负载的修改前性能，因此不作吞吐提升比例结论。

压测采用平台本地的小型脚本产物，验证编排、并发和元数据一致性。真实数据库吞吐、大备份网络传输、PB 级容量、真实 Docker/JDBC 克隆和 Windows 真机恢复仍需对应环境验证。
