## 三、详细改进设计方案（待拍板）

> 优先级原则：先补「客户可感知、招标可对照」的能力缺口；小改动高价值先行。工作量按人日（1 人日=6h 有效编码+自测）。

### P0-1 单表/逻辑表直接恢复（对标：DSG 直接逻辑表恢复、鼎甲直接逻辑表恢复）｜≈8 人日

**场景**：误 drop/truncate 表，从已有全量/全实例备份集中直接抽取该表恢复，不搭建辅助实例、不影响其他库。

**设计**：
- 新增 API `POST /api/records/<id>/table-restore`，body：`{target_db, tables:[...], target_host_id?}`；
- 引擎层 `core/table_extract.py`（新）：按库型从既有产物抽取：
  - MySQL 全实例 tar：解 tar 取 `dbs/<db>.sql` → `awk`/Python 按表边界切出 `CREATE TABLE t + INSERT` 段（`-- Table structure for table \`t\``锚点）→ 灌入目标库；
  - MySQL 单库 .sql/.sql.zst：同上按表锚点切；
  - PG/金仓/openGauss 自定义格式：`pg_restore -l` 列 TOC → `-L` 列表文件过滤该表 section → `pg_restore -L ... -d target`（原生能力，零解析）；
  - Oracle：impdp `TABLES=schema.table` 已有（复用恢复通道，补"从全库 dmp 抽表"参数透传）；
  - 达梦：dimp `TABLES=`（已有 TABLE_EXISTS_ACTION=REPLACE 链路）；
- 前端：备份记录行「单表恢复」按钮 + 弹窗（列出备份集内可抽的表清单：MySQL 从 tar 内 dbs/<db>.sql 解析表名；PG 从 TOC 列出）；
- 约束：压缩链（zst/gz）先解压为流式处理；产物锁定（locked）记录也可恢复；恢复动作进审计 + 高危验证码（见 P1-2）。
- 验收 E2E：全实例 tar 中抽单表 → 异名库恢复 → 行数/中文核对（复用 170 环境）。

### P0-2 高危操作人机验证码 + 资源受保护标记（对标：鼎甲管理安全/资源保护）｜≈4 人日

- 验证码：恢复作业、清理作业、删除备份集三类 API 前置 `POST /api/verify-code` 生成 4 位图（session 内一次性），前端弹窗输入，服务端校验后放行（复用现有 confirm 闸门机制加一层）；
- 资源保护：`servers/instances` 表加 `protected` 列（或 system_config JSON），被标记的实例**不能作为恢复目标/复制目标**（restore/pitr/clone 入口校验），备份不受影响；UI：实例列表「保护」开关 + 恢复弹窗内置灰提示。

### P1-1 自动容灾切换策略 + 切换向导（对标：DSG 自动切换/智能导航切换）｜≈10 人日

- `dr_links.failover_config` 增加自动策略：`{"auto": {"enabled": false, "check_interval": 30, "consecutive_failures": 3, "health_sql": "SELECT 1", "require_manual_confirm": true}}`；
- 后台巡检线程（复用 rt_supervisor 心跳节拍）：连续 N 次探测失败 → 产生「切换预案待执行」告警；`require_manual_confirm=false` 时自动执行 failover（默认 false，安全第一）；全过程写切换历史（已有 failover_history）；
- 切换向导 UI：drlink 页新增「容灾切换向导」——预检（主库状态/复制延迟/分叉预判）→ 确认页（显示将执行的 6 步 + RPO 预估损失）→ 执行（步骤进度条）→ 结果（RTO/切换报告）。手动一键切换也走此向导。

### P1-2 Oracle 事务级精准还原（对标：鼎甲 Oracle 事务级精准还原）｜≈12 人日

- 地基：LogMiner 捕获已产出含 redo/undo SQL 的 jsonl（时间/SCN/表/操作/SQL/UNDO）；
- 新增「事务浏览」：解析 jsonl 按事务（XID）聚合 → 时间轴展示（时间/SCN/用户/表/操作类型/行数）→ 事务详情（逐条 SQL + UNDO SQL）；
- 新增「精准回滚」：选择事务/时间点/SCN → 生成并执行 UNDO SQL（先 dry-run 展示将执行的回滚语句 → 二次确认 → 执行 → 影响行数回报）；
- 边界如实：仅覆盖已捕获的实时链路库型（Oracle 11g/19c 真机已验证 LogMiner）；MySQL 等价能力走 binlog PITR（已有）。

### P1-3 池复制：两地三中心编排（对标：鼎甲池复制）｜≈10 人日

- `storage_pools` 概念实体化（复用 storage_targets）：池=备份存储目标；新增「池复制作业」：源池→目标池（本地/异地），按备份集增量复制（只传新备份集 + rsync delta/断点续传）；
- 两地三中心模板：本地池→同城池→异地池链式作业 + 拓扑图展示（每备份集在哪些中心有副本、副本数）；
- 反向取回：异地池备份集拉回本地恢复（跨中心恢复入口）；
- 调度：cron 化，弱网络下走断点续传（已有）。

### P1-4 文件推送式实时同步（对标：DSG 文件级容灾）｜≈12 人日

- 平台侧 inotify 不可行（零 Agent），采用**轮询+指纹**推送模式：远端周期 `find -newer` 指纹清单（复用 remote_file_manifest）→ 差异集 → SFTP/rsync 推送到目标端；
- 同步方式：全量/差异/定时/近实时（间隔可配，秒级靠 rsync delta）；文件比对=大小+mtime+sha256（与 DSG 同口径）；
- 容灾切换联动：文件同步对绑定 dr-link，切换时 DNS/预案引用；
- 与既有「文件镜像备份」互补：镜像=备份产物落镜像树；本项=源→目标直接同步容灾。

### P1-5 单任务多通道并行（对标：鼎甲 256 通道）｜≈8 人日

- 任务 extra `parallel_channels`（默认 1，上限 16）：文件备份按目录切分多通道并发拉取；Oracle RMAN `ALLOCATE CHANNEL n`（推送到远端的 rman 脚本按通道数生成）；对象存储/HDFS 类天然可并发分片；
- 限速按通道均分；进度=各通道聚合。

### P2 池（按价值排序，均给出口径，拍板后另出细化排期）

1. **三员管理+登录强化**（审计员/安全保密员/系统管理员三权分立 + 登录失败锁定 + 多因子可选）≈6 人日——政企投标硬指标；
2. **报表中心**（作业/存储/演练 RTO 趋势报表页 + 定时邮件，复用现有邮件通道）≈5 人日；
3. **数据库日常监控**（实例级自定义 SQL 指标 → 图表页，复用巡检/探针通道）≈5 人日；
4. **存储池类型抽象**（本地池/重删池/合成池标签 + 池级策略：保留期/锁定默认值/池复制归属）≈4 人日；
5. **坏块检测**（Oracle RMAN `BACKUP VALIDATE`/DBV 前置校验进预检；MySQL `CHECK TABLE` 快速模式）≈3 人日；
6. **Oracle 非归档在线热备**（begin backup 表空间模式，免开归档的应急热备）≈5 人日；
7. **AccessKey 认证模式**（任务凭据支持 AK/SK 免密轮换）≈4 人日；
8. **多租户/分级管理**（组织树+租户隔离+配额）≈15 人日（大件，建议有客户订单再启动）；
9. **SNMP 告警对接**≈2 人日；**大屏**≈4 人日；**时间段限速策略**≈2 人日；
10. **信创分布式数据库接入**（TDSQL-PG/OceanBase/TiDB 复用 PG/MySQL 引擎适配）≈每库 3-5 人日，按需。

### 不跟随清单（维持差异化定位）

| 项 | 原因 |
|---|---|
| 卷级 CDP/主机双活（内核驱动） | 违反零 Agent 架构；等效能力=实时日志备份+PITR |
| 物理块挂载即时恢复（VDisk） | 需存储层驱动/内核模块；等效=克隆/黄金副本+应急实例接管 |
| 生产端必装 Agent 的交易复制 | AIDBM 数据库复制走日志协议（binlog/WAL/LogMiner）零安装 |
| Exchange/Domino/SharePoint、NDMP、HDFS/Hive、SAP HANA/Caché | 离线数据库灾备定位外，有订单再立项 |
| 裸机恢复（P2P/P2V 驱动注入） | 需 WinPE/引导镜像体系，与数据库灾备定位偏离 |
