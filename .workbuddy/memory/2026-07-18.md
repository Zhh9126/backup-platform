## 巡检引擎误报"警告"修复
- **根因**：原 `_inspect_one` 对所有任务（包括 file 类型）跑 DB 连通性探测，得到 `ok=None → warn`；加上手动任务未配置调度也 warn；总体被判定为「警告」，即使上次备份是 success。
- **`core/inspection.py` 重构**：
  - 拆分为 `_inspect_db_task` 与 `_inspect_file_task`，按 db_type 走不同维度。
  - **DB 任务**：未配置 host → warn（不 fail）；客户端未实现探测但 host 已配 → ok。
  - **文件任务（remote）**：检查 SSH 主机是否在 ssh_hosts 中（按 id 或 host_key 匹配），匹配到或 host_key 已存在（能跑）→ ok。
  - **文件任务（local）**：检查源路径是否存在，不存在 → fail，存在 → ok。
  - 文件任务调度不强制（手动执行是常见合法用法）。
  - 「上次运行」独立出来作为通用关键指标：success/simulated/running → ok，failed → fail，never → warn。
- **测试验证**：7/7 PASS — DB任务+success→pass、DB任务无host→warn、DB任务fail→fail、文件remote+success→pass、文件local+success→pass、文件fail→fail、文件never→warn。

## 文件备份运行中显示"失败"误判 + SSH 鲁棒性增强
- **核心问题**：用户截图看到任务状态"失败"但日志显示"备份中"。原因是上一次失败状态（SSH连接 15s 超时）覆盖不到本次，UI 一直停留在上次的"失败"。
- **核心修复**：在 `core/scheduler.py` `_execute_backup` 启动时立即调用 `models.set_task_status(task_id, started, "running")`，让 UI 实时显示"备份中"。
- **`core/engines/file.py` SSH 鲁棒性**：
  - `_get_ssh_client` 的 `client.connect(timeout=60)`（15s→60s，慢网络更友好）
  - 连接池取出时先 `t.is_active()` 检查死连接并丢弃（避免复用 stale 连接）
  - `_ssh_exec_pipe` 加 30s 心跳日志，让长时间无输出的命令也能看到进度

## 架构升级：物理备份 + 逻辑备份双模式（所有引擎）
用户需求：MySQL/PostgreSQL/Oracle/达梦/金仓 都应有物理备份和逻辑备份两种模式，参考 mysql_backup_webtool 的完整代码做分库分表备份。

### 架构变更
- **`core/engines/base.py`**：新增 `BackupMode` 枚举（`LOGICAL` / `PHYSICAL`）、`backup_mode` 属性、`extra` 属性。
- **`core/db.py`**：`backup_tasks` 表新增 `backup_mode TEXT DEFAULT 'logical'` 列；`init_schema()` 加 ALTER TABLE 迁移逻辑（幂等）。
- **`core/models.py`**：`TASK_FIELDS` 加 `backup_mode`。
- **`api/system.py`**：`/api/meta` 返回 `backup_modes` 字典供前端渲染。

### 引擎改造

| 引擎 | 物理备份 | 逻辑备份 |
|------|----------|----------|
| **MySQL** | `xtrabackup --backup --no-lock`（全量/增量） | `mysqldump`（分库/分表/仅结构/仅数据，由 extra_options.tables/schemas/schema_only/data_only 控制） |
| **PostgreSQL** | `pg_basebackup -D DIR -Ft -z` | `pg_dump`（已有） |
| **Oracle** | RMAN（`BACKUP DATABASE` / `BACKUP INCREMENTAL LEVEL 0`） | `expdp`/`exp`（已有） |
| **Kingbase** | `sys_basebackup -D DIR -Ft -z` | `sys_dump`（已有） |
| **Dameng** | `dmrman`（写入 cmd 脚本执行） | `dexp`（已有） |

每个引擎 `backup()` 通过 `self.backup_mode` 分发改物理/逻辑，逻辑沿用原有实现（兼容）。

### 逻辑备份粒度增强（MySQL）
`_backup_logical` 支持 extra_options 中的粒度字段：
- `tables: ["t1","t2"]`：`mysqldump db t1 t2`
- `schemas: ["db1","db2"]`：`mysqldump --databases db1 db2`
- `schema_only: true`：`--no-data`
- `data_only: true`：`--no-create-info`
